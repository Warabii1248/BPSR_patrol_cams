# /changelog — changelog エントリ自動生成

## 目的

`changelog.txt` に CLAUDE.md §7 のテンプレに沿った新規エントリを冒頭に挿入する。
- No.NN は既存最大 +1 を自動採番
- 日時は実行時刻
- 引数があれば一行サマリに流し込む
- 背景/変更/効果/影響範囲は **空欄テンプレで残す**（ユーザーが埋める）

## 実行手順

1. **最新 No.NN を取得**

   ```bash
   grep -oE "^\[No\.[0-9]+\]" changelog.txt | sort -t. -k2 -n | tail -1
   ```

   出力例 `[No.35]` → 次は **No.36**。0 件なら No.01。

2. **現在時刻を取得**（PowerShell）

   ```powershell
   Get-Date -Format 'yyyy/MM/dd HH:mm'
   ```

3. **changelog.txt の先頭エントリを Read で取得**

   1行目は区切り `====---...` で、2行目に `[No.NN] yyyy/mm/dd hh:mm — サマリ` がある。

4. **Edit で新エントリを既存最新エントリの直前に挿入**

   `old_string` には現状の1行目 `====---...` を含めて捉え、`new_string` に新エントリ + 既存1行目 をつなぐ。

   挿入する新エントリ本体（`<引数>` は呼出引数。無い場合は `（一行サマリを記入）`）:

   ```
   ====--------------------------------------------------------------------------------
   [No.NN] yyyy/mm/dd hh:mm — <引数または "（一行サマリを記入）">

   【背景 / 原因】
     （ここに記入）

   【変更内容】
     ファイル名:
       - （変更点）

   【効果】
     （ここに記入）

   【影響範囲】
     - （変更ファイル列挙）
     - 後方互換性: （影響なし / 旧キーフォールバック有 / 等）

   ```

   注意: 挿入後、既存先頭 `====---...` の前に新エントリが入る形になること。
   末尾の空行を1つ確保してから次の `====---` が続く。

5. **挿入が終わったら Bash で `head -25 changelog.txt` を実行して確認**を表示する。

## 注意

- `pb/bp.pb.go` 等の自動生成物の変更だけならエントリ不要（人手介入なし）
- サマリは 60 文字以内推奨
- 背景/変更/効果/影響範囲は **空欄のまま**。コミット前にユーザー or 別タスクが埋める

## 引数の扱い

- 引数あり: その文字列を一行サマリに流す（例: `/changelog ロード安定化遅延を 6s に短縮`）
- 引数なし: 一行サマリ位置は `（一行サマリを記入）` プレースホルダ

## 失敗時

- `changelog.txt` が読めない / `grep` 結果が空 → No.01 を採番してファイル先頭に新規挿入
- Edit が old_string 不一致でエラーなら Read で先頭 20 行再取得して再試行
